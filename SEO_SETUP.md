# Как сдать сайт Ponoi поисковикам

Пошагово, для владельца проекта. Всё бесплатно, платные службы не нужны нигде.
Каждый шаг занимает несколько минут; между шагами можно расходиться на дни.

Сайт уже выложен и открыт для роботов: <https://ponoiai.github.io/>. От этой
инструкции зависит только скорость — без неё поисковики найдут сайт сами, просто
через недели, а не через дни.

---

## Что уже сделано и делать не надо

- Сайт выкладывается сам при каждом изменении и каждые шесть часов (чтобы
  подхватить новый выпуск приложения).
- `robots.txt` открыт всем, включая поисковых роботов ИИ, и указывает на карту
  сайта: <https://ponoiai.github.io/robots.txt>
- Карта сайта со всеми 26 страницами и языковыми связями:
  <https://ponoiai.github.io/sitemap.xml>
- На каждой странице свой заголовок, своё описание, canonical, Open Graph,
  hreflang и структурированные данные.
- Машиночитаемая выжимка для поисковых ИИ:
  <https://ponoiai.github.io/llms.txt>
- Описание, сайт и темы репозитория `ponoiai/ponoi` заполнены.

Ниже — только то, что можно сделать исключительно руками и только под своей
учётной записью.

---

## 1. Google Search Console

1. Открой <https://search.google.com/search-console/> и войди своей учётной
   записью Google.
2. Нажми **Add property → URL prefix** (правая карточка, не левая).
3. Введи ровно:
   ```
   https://ponoiai.github.io/
   ```
4. Google предложит способы подтверждения. **Подходит только «HTML tag»** —
   способ с файлом и способ через домен на GitHub Pages не годятся: домен чужой.
   Скопируй строку вида:
   ```html
   <meta name="google-site-verification" content="ABCDEF..." />
   ```
5. Отдай мне (или впиши сам) значение `content`. Куда вписать: файл
   `src/layout.mjs` в репозитории `ponoiai/ponoiai.github.io`, сразу после строки
   `<meta name="description" ...>`:
   ```js
   <meta name="google-site-verification" content="ABCDEF...">
   ```
   После коммита в `main` сайт пересоберётся сам за пару минут.
6. Вернись в Search Console и нажми **Verify**.

> Подтверждение делается один раз. Строку потом не удалять — Google
> перепроверяет её.

## 2. Отдать Google карту сайта

1. В Search Console слева: **Sitemaps**.
2. В поле «Add a new sitemap» вписать:
   ```
   sitemap.xml
   ```
3. **Submit**. Через несколько минут статус станет «Success» и появится число
   найденных адресов — их должно быть 26.

## 3. Попросить проиндексировать главные страницы

Индексирование по карте сайта идёт своим чередом и занимает от нескольких дней.
Отдельные страницы можно попросить проверить сразу — это делается по одной.

Вверху Search Console есть поле **«Inspect any URL»**. Вставляешь адрес,
дожидаешься проверки, нажимаешь **Request indexing**. Сделать это для восьми
адресов по порядку важности:

1. `https://ponoiai.github.io/`
2. `https://ponoiai.github.io/about/`
3. `https://ponoiai.github.io/download/`
4. `https://ponoiai.github.io/security/`
5. `https://ponoiai.github.io/plugins/`
6. `https://ponoiai.github.io/privacy/`
7. `https://ponoiai.github.io/ru/`
8. `https://ponoiai.github.io/ru/about/`

Больше десяти запросов в сутки Google не принимает — остальное подождёт до
завтра, ничего страшного.

## 4. Bing Webmaster Tools

Bing — это ещё и поиск внутри Windows, и часть ответов ИИ-помощников.

1. <https://www.bing.com/webmasters/> → войти.
2. Проще всего **Import from Google Search Console** — тогда подтверждение и
   карта сайта переедут сами, и шаги 5–6 не нужны.
3. Если импорт не подошёл: **Add site**, адрес `https://ponoiai.github.io/`,
   способ подтверждения — **HTML Meta Tag**, дальше как в пункте 1 (строка
   `<meta name="msvalidate.01" content="...">` в тот же `src/layout.mjs`).

## 5. Отдать Bing карту сайта

**Sitemaps → Submit sitemap** → `https://ponoiai.github.io/sitemap.xml`

## 6. Яндекс (важно для запроса «Поной»)

Русское написание ищут прежде всего в Яндексе.

1. <https://webmaster.yandex.ru/> → **Добавить сайт** → `https://ponoiai.github.io/`
2. Подтверждение — **Мета-тег**, строка `<meta name="yandex-verification" ...>`,
   вписывается туда же, в `src/layout.mjs`.
3. **Индексирование → Файлы Sitemap** → добавить
   `https://ponoiai.github.io/sitemap.xml`
4. **Индексирование → Переобход страниц** — вписать те же восемь адресов, что и
   для Google.

## Как проверить, что всё в порядке

Всё это работает без учётных записей, прямо из браузера.

| Что | Где | Что должно быть |
|---|---|---|
| robots.txt отдаётся | <https://ponoiai.github.io/robots.txt> | текст, а не 404 |
| карта сайта отдаётся | <https://ponoiai.github.io/sitemap.xml> | XML с 26 адресами |
| разметка страницы верна | <https://validator.schema.org/> — вставить адрес | ошибок нет |
| богатые результаты | <https://search.google.com/test/rich-results> | видит SoftwareApplication на главной и FAQPage на `/faq/` |
| страница на телефоне | <https://pagespeed.web.dev/> — вставить адрес | оценки, и заодно скорость |
| ссылка в соцсетях | вставить `https://ponoiai.github.io/` в любой чат | появляется картинка и описание |

Свою проверку ссылок, заголовков, описаний и структурированных данных сайт
делает сам при каждой сборке (`node check.mjs` в репозитории сайта); если она
падает, сайт не выкладывается вовсе.

## Чего делать не надо

- **Не покупать ссылки и не регистрироваться в каталогах.** Это работало
  пятнадцать лет назад, а сейчас приносит только пометку о спаме.
- **Не набивать страницы словами.** «Ponoi» и «Поной» встречаются на сайте
  столько раз, сколько нужно по смыслу; больше — хуже.
- **Не создавать отдельные страницы под каждый запрос.** Одна тема — одна
  страница, у каждой свой постоянный адрес: этого достаточно и это то, что
  поисковики любят.
- **Не торопить.** Новому сайту нужно от нескольких дней до пары недель, чтобы
  появиться по запросу «Ponoi», и дольше — чтобы обогнать одноимённую реку в
  Мурманской области по запросу «Поной». Это нормально.

## Когда появится собственный домен

Если однажды будет куплен домен (например `ponoi.app`):

1. В репозитории сайта поменять `ORIGIN` в `src/site.mjs` — от него считаются
   все canonical, hreflang, карта сайта и `llms.txt`.
2. Положить файл `CNAME` с доменом в `assets/` и добавить его копирование в
   корень в `build.mjs`.
3. В настройках DNS домена — записи GitHub Pages, в настройках репозитория —
   Custom domain и **Enforce HTTPS**.
4. В Search Console, Bing и Яндексе завести новый ресурс и сделать
   **переезд сайта** (Change of Address), а не заводить его заново с нуля.
5. Прежний адрес не удалять: `ponoiai.github.io` продолжит работать и будет
   пересылать на новый.
